# 기술 설명

## 한글 출력 방식 (영어 전용 게임)
- 글꼴은 1바이트 256자(YCHR 셀 표 + 4bpp TIM2)이고, 메뉴 글꼴 VRAM 영역이 거의 꽉 차 있어 한글 텍스처를 상주시킬 자리가 없음.
- **동적 글리프 업로드**: 한글은 Shift-JIS 호환 2바이트 코드(리드 0x81~0x9F·0xE0~0xEF, 트레일 0x80~0xFC)로 인코딩.
  `CFontDraw::GetFontCell` 훅이 한글이면 각 폰트 텍스처 안의 "슬롯" 칸을 가리키는 셀을 돌려주고,
  `SpriteShow`/`ShowFast` 직전 훅이 같은 DMA 체인(VIF1 DIRECT)에 BITBLTBUF/TRXPOS/TRXREG/TRXDIR + IMAGE + TEXFLUSH 패킷을
  넣어 그 슬롯에 글리프를 올린 뒤 바로 그림. VRAM 추가 사용 없음.
- 슬롯 정보는 각 YCHR 의 빈 코드 0x1C~0x1F 셀에 기록(표시 크기, UV 창, 업로드 위치, 글리프 크기/팔레트).
- 글리프: **나눔스퀘어네오 ExtraBold**(원본 굵은 산세리프와 유사) 24px·16px, 글로/외곽 레이어용으로 굵게 번진 16px 세트.
  2bpp로 실행 파일 뒤 새 적재 구간(0x5A1000~)에 두고 업로드 때 4bpp로 펼침. 힙 시작(crt0·main·sbrk heap_ptr)을 뒤로 이동.
- 빈 공간이 없던 폰트는 영문판에 안 쓰는 가타카나·라틴 확장 글리프를 빼고 텍스처를 재배치(메인 글꼴 256×512→256×256 등)해
  그 VRAM으로 다른 글꼴 텍스처를 키움(총량 감소). 경기 중 대문자 글꼴(128×64)은 같은 시점에 상주하는 경기 글꼴의 슬롯을 빌려 씀.
- 일본판 잔존 코드가 0x81~ 로 시작하는 문자열을 '한자 문자열'로 분류하는 문제 → 한자 모드도 영문 표 경로를 타도록 수정.


## 자료 형식
- `PAC/*.PAC`: DPAC 묶음(0x800 디렉터리: 이름 4바이트 + 시작 섹터 u16 + 크기/256 u16, 데이터 0x4000부터). 항목은 `PAC `(id u16, 오프셋 u24, 크기 u24) 묶음이며 내용은 Gage BPE 압축(블록 크기 u16 LE, 4000바이트 블록).
- 글꼴: TIM2(4bpp, 흰색 알파 단계 CLUT) + YCHR(셀 x,y,w,h, 1바이트 256자).
- 시즌 대사 MISC.PAC STDE/TTDE: u16 개수 + (u16 번호, u16 길이(4배수), 문자열) 레코드. 블록은 파일 끝에 새로 두고 디렉터리를 갱신.
- 선수 마스터 M.PAC `MOT/CHAR/ALL`: 365바이트 레코드, 이름 278(22) / 별명 300(24) / 호칭 324(23).
- 실행 파일 UI 문자열: 제자리에 들어가면 덮어쓰고, 넘치면 새 적재 구간에 두고 데이터 포인터·lui/addiu 참조를 고침.

## 표시 시점 이름 치환
메모리 카드 시스템 데이터에 선수 이름이 저장되므로, `CFontDraw::ShowString`·`GetFontWidth`·`ShowFast` 진입에서 문자열 해시(h*31+c)를 이진 탐색해 영어 선수 이름이면 한글 문자열로 바꿔 그립니다.

## 이미지 문자
로딩 팁·PPV 소개·경기 중 그림은 흰 글자 영역을 OpenCV 인페인팅으로 지우고 한글을 다시 그린 뒤 원래 팔레트로 되돌립니다(`tools/tips.py`, `tipspec.py`, `imgpatch.py`).
